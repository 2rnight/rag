
# 智远科技 技术开发规范 V2.0

## 1. 代码规范

### 1.1 Python 编码规范
- 遵循 PEP 8 编码风格指南
- 使用 4 个空格缩进，禁止使用 Tab
- 每行代码不超过 120 个字符
- 类名使用 CamelCase，函数和变量名使用 snake_case
- 常量使用全大写加下划线：MAX_RETRY_COUNT
- 所有公开函数必须编写 docstring
- 类型注解（Type Hints）为强制要求

### 1.2 Git 提交规范
提交信息格式：<type>(<scope>): <subject>

类型说明：
- feat: 新功能
- fix: 修复bug
- docs: 文档更新
- style: 代码格式调整
- refactor: 代码重构
- test: 测试用例
- chore: 构建/工具变动

示例：
- feat(user): 添加用户注册功能
- fix(auth): 修复token过期未刷新问题
- docs(api): 更新接口文档

### 1.3 分支管理
- main: 生产环境分支，只接受合并，不直接提交
- develop: 开发主分支
- feature/xxx: 功能开发分支
- hotfix/xxx: 紧急修复分支
- release/xxx: 发布分支

工作流程：
1. 从 develop 创建 feature 分支
2. 开发完成后提交 Pull Request
3. 至少需要 2 位同事 Code Review
4. CI/CD 测试通过后合并到 develop
5. 发布时从 develop 创建 release 分支
6. 测试通过后合并到 main 并打 tag

## 2. 数据库规范

### 2.1 命名规范
- 表名：小写，下划线分隔，复数形式（如 users, order_items）
- 字段名：小写，下划线分隔（如 created_at, user_name）
- 索引名：idx_表名_字段名（如 idx_users_email）
- 主键：统一使用 id，类型为 BIGINT 自增

### 2.2 设计规范
- 所有表必须包含以下字段：
  - id: BIGINT, 主键自增
  - created_at: DATETIME, 创建时间
  - updated_at: DATETIME, 更新时间
  - is_deleted: TINYINT, 软删除标记（0:正常, 1:已删除）
- 禁止使用外键约束，在应用层处理关联
- 单表数据量超过 1000 万行需进行分表
- 字符串字段默认使用 VARCHAR(255)，超长文本使用 TEXT
- 金额字段使用 DECIMAL(10,2)，禁止使用 FLOAT

### 2.3 SQL 规范
- 禁止使用 SELECT *
- 大表查询必须带有索引条件
- 禁止在 WHERE 条件中对字段进行函数运算
- UPDATE/DELETE 操作必须带 WHERE 条件
- 批量操作使用批量 SQL，单次不超过 1000 条

## 3. API 设计规范

### 3.1 RESTful 规范
- 使用名词复数形式作为资源路径：/api/v1/users
- HTTP 方法语义：
  - GET: 查询资源
  - POST: 创建资源
  - PUT: 全量更新资源
  - PATCH: 部分更新资源
  - DELETE: 删除资源

### 3.2 响应格式
统一响应格式：
{
    "code": 200,
    "message": "success",
    "data": {},
    "timestamp": 1704067200
}

错误码规范：
- 200: 成功
- 400: 请求参数错误
- 401: 未授权
- 403: 无权限
- 404: 资源不存在
- 429: 请求频率超限
- 500: 服务器内部错误

### 3.3 安全规范
- 所有接口使用 HTTPS
- 认证使用 JWT Token，有效期 2 小时
- 敏感操作需二次验证
- 接口限流：默认 100次/分钟/用户
- 请求参数必须进行校验和过滤
- 日志中禁止记录敏感信息（密码、token等）

## 4. 测试规范

### 4.1 测试要求
- 单元测试覆盖率不低于 80%
- 核心业务逻辑覆盖率不低于 95%
- 所有 API 接口必须有集成测试
- 使用 pytest 框架
- 测试文件命名：test_模块名.py

### 4.2 测试环境
- dev: 开发测试环境
- staging: 预发布环境（与生产环境配置一致）
- prod: 生产环境

## 5. 部署规范

### 5.1 容器化要求
- 所有服务必须 Docker 容器化
- 使用多阶段构建优化镜像大小
- 基础镜像统一使用 python:3.11-slim
- 健康检查接口：GET /health
- 就绪检查接口：GET /ready

### 5.2 监控告警
- 应用指标：QPS、响应时间、错误率
- 系统指标：CPU、内存、磁盘、网络
- 告警阈值：
  - CPU > 80% 持续 5 分钟
  - 内存 > 85% 持续 5 分钟
  - 错误率 > 1% 持续 3 分钟
  - 响应时间 P99 > 3秒
- 告警通知：企业微信 + 邮件 + 电话（P0级别）

### 5.3 日志规范
- 日志格式：JSON 格式，包含 timestamp, level, service, trace_id, message
- 日志级别：DEBUG < INFO < WARNING < ERROR < CRITICAL
- 生产环境日志级别：INFO
- 日志保留时间：30天
- 使用 ELK 栈进行日志收集和分析
